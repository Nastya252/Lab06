## Итоговый вопрос
CPU умеет выполнять инструкции только из оперативной памяти, у него нет прямого доступа к файлам на накопителе, а диск слишком медленный, чтобы снабжать процессор командами на скорости его работы. Поэтому между диском и процессором работают операционная система(по команде запуска находит файл на накопителе, читает его, создаёт процесс) и оперативная память(принимает загруженную программу)

## Контрольные вопросы 
1. Чем файл программы на HDD/SSD отличается от работающего процесса?  
Файл - сохранённые данные: набор инструкций и ресурсов, которые сами по себе ничего не делают. Процесс - активная работающая копия программы, которой ОС выделила память

2. Зачем программе нужна оперативная память после запуска?  
CPU не может выполнять инструкции прямо с накопителя

3. Как по Диспетчеру задач можно увидеть, что программа действительно работает?  
В Диспетчере задач появляется запись о процессе с именем программы, его PID

4. Почему во время вычислений увеличивается загрузка CPU?  
Во время вычислений CPU непрерывно выполняет огромное кол-во инструкций цикла и его загрузка резко растёт

5. Остаётся ли файл программы на HDD/SSD после завершения процесса?  
Да, остаётся. Завершение процесса уничтожает только копию программы в памяти

## Итоговый вывод 
Исходная программа находится на накопителе (HDD либо SSD) в виде обычного файла - это записанные данные, которые сами по себе не выполняются. При запуске операционная система отыскивает нужный файл на диске, запускает процесс со своим уникальным PID и помещает копию программы в оперативную память (RAM). В RAM программа занимает рабочую область под код - оттуда процессор (CPU) считывает и исполняет команды, ведь напрямую с накопителя он выполнять инструкции не может. Когда работа заканчивается, процесс прекращает существование и память освобождается, тогда как файл программы на диске остаётся нетронутым и доступен для повторного запуска.
